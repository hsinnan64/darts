# 飛鏢投擲骨架分析器

用瀏覽器分析飛鏢投擲動作的個人工具。上傳影片後，會即時標出身體骨架與手腕移動軌跡，用來檢視每次出手的動作是否一致。

**線上使用**：https://hsinnan64.github.io/darts/

## 特色

- **影片不會上傳** — 所有運算都在瀏覽器本機完成，影片與分析結果不會傳到任何伺服器
- **免安裝** — 開啟網頁即可使用，手機與電腦都能跑
- **穩定追蹤** — 針對手臂快速揮動時容易跳點的問題做了多層處理

## 功能

| 功能 | 說明 |
|---|---|
| 骨架顯示 | 標出上半身與下半身的關鍵點與連線 |
| 手腕軌跡 | 畫出投擲手的手腕移動路徑 |
| 每鏢不同色 | 每一鏢換一個顏色，多鏢疊在一起就能看出每次出手的落差 |
| 鏢次圖例 | 資訊區列出目前畫面上每一鏢的顏色，正在進行的那一鏢會標示出來 |
| 投擲手判定 | 自動判斷左右手，只畫實際在動作的那隻手 |
| 出手偵測 | 只在手腕高過手肘期間畫軌跡，準備與收手動作不會汙染畫面 |
| 純黑背景 | 隱藏影片畫面，只留點、線與軌跡，專注看動作本身 |
| 錄製下載 | 把含骨架與軌跡的畫面錄下來存檔 |

## 使用方式

1. 開啟網頁，等待骨架模型載入完成
2. 點「選擇影片」載入要分析的影片（建議 H.264 編碼的 MP4）
3. 點「播放」開始分析
4. 需要時切換「背景：純黑」或開啟「錄製」

### 拍攝建議

- 側面拍攝，讓投擲手臂完整入鏡不被身體擋住
- 光線充足、背景單純，追蹤會更穩定
- 手機慢動作模式（120fps 以上）能捕捉到更細的出手動作

## 技術架構

純前端單頁應用，無後端、無資料庫、無建置流程。

- **姿態辨識**：[MediaPipe Tasks Vision](https://github.com/google-ai-edge/mediapipe) — `pose_landmarker_full` 模型，GPU 加速
- **繪製**：Canvas 2D
- **錄製**：`canvas.captureStream()` + `MediaRecorder`
- **流量統計**：Google Analytics 4 — 需使用者同意後才啟用

統計的評估 ID 設定在 `analytics.js` 最上方的 `MEASUREMENT_ID`（`G-` 開頭），三個頁面共用同一份。

採取「預設不追蹤」：使用者按下同意橫幅的「同意」之前，完全不載入 GA、不發出任何對 Google 的連線、不寫入任何 Cookie。這比 Google Consent Mode 的預設拒絕更嚴格 — Consent Mode 在拒絕狀態下仍會送出無 Cookie 訊號，這裡是連 `gtag.js` 都不下載。選擇記在 `localStorage.darts_analytics_consent`。

`MEASUREMENT_ID` 留空時橫幅不會出現、GA 也不會載入，等於整支停用，因此本機開發不會污染統計數字。

同意橫幅的文案自帶 zh / en / ja / ko 四語翻譯表（`analytics.js` 的 `TEXT`）。index.html 的 `I18N` 在 module scope 內、外部腳本讀不到，所以不共用，但語言來源一致，都讀 `localStorage.darts_lang`；index.html 切換語言時會發出 `darts:langchange` 事件讓橫幅跟著重繪。

### 關於追蹤穩定度

手腕、手肘在快速揮動時動態模糊嚴重，姿態模型輸出的座標容易單幀誤判。程式裡用了幾層處理來壓住這個問題：

1. **離群點拒絕** — 單次偵測位移超過物理上限時，判定為誤判並沿用前一個可信位置
2. **中位數濾波** — 5 幀視窗，吃掉連續誤判造成的尖刺
3. **One Euro Filter** — 時間平滑，手臂關鍵點套用較強的濾波參數
4. **可信度門檻** — 低於門檻的關鍵點不繪製、不納入軌跡，避免亂拉線

### 關於出手偵測

準備階段（拿鏢、垂手、調整站位）手腕大多低於手肘且到處晃，把那段畫進軌跡只會讓畫面糊成一團。所以軌跡**只在手腕高過手肘的期間累積**：舉起來才畫，放下去就停。

用高度（垂直）而不是前後（水平）判斷，好處是不必知道人面向哪一邊 — 側面拍攝面向左或右都成立，正面拍攝也一樣能用。

### 遲滯：開始與停止用不同門檻

| 常數 | 預設 | 作用 |
|---|---|---|
| `THROW_START_MARGIN` | 0.02 | 未累積時，要高過手肘這麼多才**開始** |
| `THROW_STOP_MARGIN` | 0 | 累積中時，要掉到低於手肘才**停止** |

兩者若相同，手腕剛好停在手肘高度附近時會每幀反覆開關，軌跡被切成一堆碎片。錯開之後，進入要明確、離開才乾脆。

太晚開始就把 `THROW_START_MARGIN` 調小，準備動作還是被畫進去就調大。

### 分段：中斷處不連線

軌跡以「段」為單位保存（`trace.segments`）。手腕放下時會在該處留一個中斷，再舉起時另起一段。

這是必要的 — 若所有點擠在同一個陣列裡，第二次舉手時會從上一段的結尾直接拉一條直線到新的起點，畫面上出現一條實際上不存在的軌跡。連投多鏢時每一鏢都是獨立的一筆。

穩定度的「移動幅度」仍跨所有段一起計算：中斷只代表那段時間沒在記錄，不是要分開評估。

座標系注意：正規化座標的 y 軸**向下增加**（畫面頂端是 0），所以「手腕高於手肘」的條件是 `elbow.y - wrist.y > 門檻`。

### 配色：依鏢次，不依部位

同一鏢的手腕、手肘、頭部、肩膀共用一個顏色，下一鏢換下一個顏色（6 色循環：橘、黃、綠、青、藍、紫）。多鏢疊在同一張畫面上，就能直接看出每次出手的落差。

刻意不用紅、白、黑：紅容易和畫面上的警示、鏢靶、衣物混淆；白會跟骨架的頸線分不出來；黑在純黑背景模式下等於看不見。

六個色相盡量拉開（最小間距 30 度，橘與黃相鄰是色相本身的限制），亮度逐色微調，確保在純黑背景上的對比都在 6.5:1 以上 — 黃綠區人眼最敏感所以壓低，藍紫區天生偏暗所以拉高，否則純藍在黑底上會暗到看不清楚。

部位靠位置區分而不是顏色 — 手腕畫得最遠、頭部在最上方。

顏色索引存在每一段裡，不是靠陣列位置算。所以即使舊的段因為點數上限被丟棄，剩下的段顏色也不會跟著位移。

### 關於軌跡的平滑

出手瞬間手腕移動極快，一幀只能取到一個點，相鄰兩點在畫面上可能隔很遠，直接連線看起來就是生硬的直線。繪製時改用 **Catmull-Rom 曲線插值**：曲線會通過每一個實際偵測點，中間依前後鄰點的走向補出圓滑路徑，插值密度跟著點距走（`TRACE_SAMPLE_PX`，約每 6 畫素補一點）。

**這只是讓畫出來的線變順，並沒有還原沒被拍到的動作。** 要真的看到更多細節只能提高拍攝幀率 — 手機慢動作 120fps 以上差異很明顯。另外一鏢若只取到兩個點，沒有鄰點可參考，畫出來仍然是直線。

另外偵測是**每個影片幀都執行**，不做固定毫秒節流 — 節流會讓偵測慢於畫面更新，中間的幀重複套用舊座標，視覺上就是一停一跳的階梯感。

建議使用最新版 Chrome 或 Edge。需要支援 WebAssembly、WebGL 與 `MediaRecorder`。
